# Берлога — оформление Python в Go

Источник: работающая Python-установка `/opt/vivid-bot` на `alex-nether`,
снимок от 16 ноября 2026 года. Исходный Python-проект не изменялся.

Сохранены оригинальные логотипы и фоновая сцена из `customization/assets`,
а также собранный CSS живого сайта — `static/berloga/python.css`.
Oswald и Share Tech Mono хранятся локально вместе с лицензиями OFL;
внешний шрифтовой хостинг при открытии страницы не требуется.

Адаптация разметки Go вынесена в `static/berloga/go.css`. Каркасы публичных
страниц и админки используют ту же шапку, фон, подвал и типографику.
Перенесены витрина с пропуском и тарифной лесенкой, оформление, вход,
кабинет с раскрывающимися настройками, поддержка и переписка.
Формы, CSRF, авторизация, оплата и SSE используют существующие обработчики Go.
Это перенос оформления и структуры страниц, а не перенос всех функций Python.

## Установка

Каталог темы целиком копируется на сервер. `WEB_DIR` указывает на этот
каталог; при контейнерном запуске он монтируется в `/app/web`.
После обновления файлов приложение нужно перезапустить.

В `theme.json` по умолчанию задано `data.environment=production`.
Для тестового стенда значение `development` включает соответствующую пометку.
Условия пробного доступа, тарифы, цены и количество устройств берутся
из настроек и базы работающего Go-сервиса.

Локальная проверка на изолированной БД `vivid_ui_lab`:

```powershell
go run ./cmd/screenlab -serve -port 8099 -theme web/themes/berloga
```

Требуется `VIVID_LAB_DATABASE_URL` с loopback-адресом и портом `55439`.
Локальный пульт создаёт демо-сессию, поэтому его нельзя публиковать в интернете.

Перед выкладкой проверяются контракты шаблонов на госте, активной и пустой
подписке, тарифах, поддержке и административных страницах. Отдельно проверены
узкий экран кабинета, выбора тарифа и поддержки, а также переход из очереди
в обращение.

В ходе проверки также исправлен поток живых сообщений Go: HTTP-логирование
больше не скрывает поддержку flush, сотрудник может подписаться на доступное
ему обращение, а просмотр сотрудником не помечает ответ прочитанным клиентом.

Оформление Telegram находится в `bot.json`: персонаж, тексты, названия действий
и расположение кнопок. Для rich-таблиц требуется `RICH_MESSAGES_ENABLED=true`;
`BOT_STYLE=legacy` поддерживает эти экраны. После обновления JSON бот перезапускается.
