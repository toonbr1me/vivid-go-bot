# Автопродление

Включение в окружении:

```dotenv
PAYMENTS_RECURRING_ENABLED=true
PAYMENTS_RECURRING_PROVIDERS=yookassa,platega
```

Эти настройки разрешают предложение автопродления. У магазина должны быть
подключены соответствующие возможности провайдера. Галочка в оформлении
выключена при новом выборе тарифа. При включении остаются только поддержанные
пары: ЮKassa / банковская карта и Platega / рекуррентная СБП-подписка.
Названия провайдеров сохраняются. Несовместимый callback отклоняется также
на сервере. Баланс, Stars и остальные разовые способы при включённой галочке
не предлагаются.

До создания счёта показываются сумма регулярного списания, период и способ
отключения. Согласие, сумма и срок сохраняются в `recurring_agreements`.
Одновременно разрешено одно включённое соглашение на аккаунт. Кнопка
«Отключить автопродление» находится в аккаунте. Согласие на автопродление не
является фактом оплаты: доступ выдаётся только за проверенное списание.

## ЮKassa

Первый платёж сохраняет способ через `save_payment_method=true`. Идентификатор
принимается только из платежа, повторно проверенного через API ЮKassa,
с `payment_method.saved=true`. Данные карты в приложении не хранятся.
После выдачи первого заказа планировщик назначает списание на окончание доступа.
Следующий запрос использует `payment_method_id` и собственный постоянный
`Idempotence-Key`. Заказ сохраняется перед запросом; после перезапуска
продолжается тот же заказ. Если результат потерян более 23 часов, автопродление
останавливается для ручной сверки: истёкший ключ нельзя безопасно повторять.
Отказ списания останавливает соглашение. Изменение базовой цены или срока
тарифа требует нового согласия. Зафиксированная скидка не увеличивается
автоматически при следующем списании.

## Platega

Создание подписки идёт через `/transaction/process`, `paymentMethod=6`.
Период задаётся в днях, совпадающих с тарифом: `interval=1`,
`intervalCount=days` (1–730). **Такой период должен быть согласован с Platega:**
нестандартные периоды зависят от тарифа мерчанта. Настройку провайдера следует
включать после согласования. Telegram-покупатель идентифицируется как
`<telegram_id>@telegram.org`, согласно документации провайдера.

Ответ создания содержит идентификатор подписки, а не оплаченной транзакции.
Привязка и регулярные списания выполняются Platega. Доступ выдаётся только по
авторизованному callback со статусом `CONFIRMED`, `subscriptionId`, уникальным
идентификатором транзакции и совпадающими суммой/валютой. Каждое новое списание
создаёт отдельный заказ. Повтор callback находит тот же заказ и не добавляет
дни повторно. Отмена сначала подтверждается через
`POST /subscription/{id}/cancel`, затем фиксируется локально.

Выключение env-флага запрещает новые предложения и останавливает планировщик
ЮKassa. Уже созданные подписки Platega нужно отменять у провайдера через кнопку
аккаунта: их расписанием управляет Platega. Отключение предложения в интерфейсе
само по себе не отменяет внешнее соглашение. Уже завершённое списание получает
доступ даже если пользователь успел отключить дальнейшие списания.

Провайдерские тесты используют поддельные HTTP API и отдельную PostgreSQL.
Для выпуска нужны проверка разрешений магазина и прогон в тестовом режиме
провайдера; реальные списания при разработке не выполнялись.
