# Интерфейс бота и пульт оператора

Режим задаёт владелец через `.env`: `BOT_STYLE=legacy` — обычные rich-сообщения,
`BOT_STYLE=html` — интерактивная карточка. По умолчанию используется legacy.
Старые персональные предпочтения не перекрывают настройку окружения; выбора
режима при `/start` и закреплённого селектора больше нет. `STYLE` поддерживается
как запасное имя переменной, если `BOT_STYLE` не задан.

При `BOT_CLEAN_CHAT=true` команды удаляются после успешной доставки ответа.
`/start` и команды разделов создают новую HTML-карточку; прежняя удаляется только
после отправки и сохранения новой. Навигация и ввод текста обновляют текущую.
Если Telegram запрещает отправку нового документа, совместимая старая карточка
обновляется; дополнительное подтверждение в чат не отправляется.
Сообщения пользователя в поддержку удаляются только после успешного сохранения
в БД. Переписка доступна в «Истории обращений» отдельной карточкой, с переходами
между сообщениями. Неудачное сохранение не удаляет исходный текст. Удаление
выполняется только в личном чате; ограничения Telegram не блокируют работу бота.

HTML-шаблоны и CSS: [инструкция](../web/bot/html/README.md).
Оплата и галочка автопродления: [автоплатежи](recurring-payments.md).
Подключение открывает выбор Happ, Incy, Clash Mi и FlClashX, затем HTTPS-мостик
передаёт ссылку установленному приложению. Ручное копирование остаётся доступным.
Проверка подписки подтверждает срок, ссылку и места; она не проверяет сеть
устройства пользователя.

## Оформление

Файл `WEB_DIR/bot-theme.json` задаёт начальное оформление. Можно скопировать
`web/bot-theme.example.json`. Все поля необязательны; отсутствующие берутся
из стандартной темы. Неизвестные поля и произвольный CSS запрещены.

| Поле | Значения |
| --- | --- |
| name | Название, до 48 символов |
| accent | `telegram` или `#RRGGBB` |
| radius | 4–20 px |
| spacing | 8–20 px |
| button_height | 40–48 px |
| heading | `balanced`, `compact` |
| navigation | `bottom`, `top` |

Владелец может изменить тему в `/admin/appearance`. Результат сохраняется
в app_settings с ключом BOT_UI_THEME и переопределяет файл. Кнопка
«Из файлов проекта» удаляет переопределение. Цвет текста акцентной кнопки
выбирается по контрасту. Обычные rich-сообщения оформляет клиент Telegram.

HTML уже отправленного виджета Telegram неизменяем. При первом переходе
после изменения темы бот создаёт новую карточку и убирает прежнюю;
дальнейшие переходы меняют только её данные. Настройки, состояние карточки
и действия сохраняются в PostgreSQL. Публичное состояние не используется.

Сайтовые шаблоны и стили настраиваются отдельно: [themes.md](themes.md).
Шаблоны `admin*.html` используют `admin_layout.html` вместо маркетинговой
оболочки сайта. Их также можно переопределить через WEB_DIR/templates.

## Пульт и быстрые действия

Веб-пульт использует существующую авторизацию и роли. Каталог и предпросмотр
темы доступны сотрудникам, сохранение темы и заказы — владельцу/администратору
в рамках существующей веб-роли Owner. Все POST-формы защищены CSRF.
`/admin/orders` показывает последние 150 заказов с поиском и фильтром статуса.
Повтор выдачи разрешён только оплаченному заказу и вызывает CheckOrder:
новый счёт не создаётся, повторные начисления защищены журналом выдачи.
В Telegram `/admin` показывает быстрый список оплаченных заказов среди
последних 50. Просмотр и повтор выдачи доступны ролям owner/admin, действия
разрешены только в личном чате. Попытки повтора записываются в аудит.

## Каталог и локальный обзор

`/admin/screens` содержит 42 экрана на демонстрационных данных: начало,
покупка, подключение, устройства, аккаунт, поддержка и ошибки. Для
HTML используются настоящие разметка, CSS и JS виджета с изолированной
демонстрационной заменой Telegram API. Для обычного режима используется
настоящий rich-рендерер. Каталог не вызывает оплату, панель или Telegram.
Он показывает варианты экранов и сценариев; реальные данные зависят от
подключённых служб и настроек проекта.

Экспорт автономного каталога:

```powershell
go run ./cmd/screenlab -export C:/path/screen-explorer.html
```

Для обзора всей админки предусмотрена отдельная команда. Она принимает
только локальную БД **vivid_ui_lab** на порту **55439**, не читает `.env`
и не использует DATABASE_URL. В ней создаются демо-владелец и примеры
заказов/обращения. Это локальный стенд с автоматической демо-сессией,
поэтому он слушает только 127.0.0.1 и не должен публиковаться наружу.

```powershell
$env:VIVID_LAB_DATABASE_URL='postgres://user:password@localhost:55439/vivid_ui_lab?sslmode=disable'
go run ./cmd/screenlab -serve -port 8099
```

В рабочем приложении автоматической сессии нет. Настройка ADMIN_IDS и
предоставление ролей выполняются обычным порядком, стенд их не меняет.

## Копирование и проверка

Защищённый виджет Telegram Web может отклонить copyText без ошибки API.
Поэтому «Получить ссылку» отправляет отдельное незащищённое сообщение со
штатной CopyText-кнопкой. Для значений длиннее лимита кнопки остаётся
копируемый код в тексте. Бот не утверждает, что буфер обмена изменён.

```powershell
node --test internal/bot/widgets/interface.test.cjs
# TEST_DATABASE_URL должен указывать на отдельную тестовую БД
go test ./...
go vet ./...
```
