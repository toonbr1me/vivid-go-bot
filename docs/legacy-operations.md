# Операции в основном legacy-интерфейсе

`BOT_STYLE=legacy` — основной режим. `RICH_MESSAGES_ENABLED=true` включает
rich API с обычным Telegram HTML fallback. Все бизнес-действия доступны
без widget API. HTML-виджеты сохраняются для дальнейшей разработки.

## Что перенесено из Python

| Сценарий | Реализация в Go |
| --- | --- |
| Рассылка | `/admin` → «Рассылка» или `/announce`: аудитория, текст, предпросмотр, подтверждение, результат |
| Кнопка промокода | `promo=КОД` в тексте: код проверяется перед созданием черновика, получателю показывается кнопка применения |
| Компенсация | Открытое обращение → «Компенсация · 3 дня», также на сайте для сотрудника |
| Первое подключение | Подписанное событие `user.first_connected` увеличивает счётчик воронки |
| Новое устройство | Подписанное `user_hwid_devices.added` ставит отдельное уведомление в очередь |

Покупки, продление, баланс, триалы, устройства, рефералы, промокоды,
опросы, партнёры и история поддержки сохраняют существующие обработчики.
Новые функции используют те же заказы, журнал выдачи и проверки прав.
Это не полная совместимость с Python: предложения пользователей,
динамические Python-расширения и предупреждения о порогах трафика не перенесены.

## Рассылки

Нужно право `broadcast.send`: владельцы из `ADMIN_IDS` и активные роли
`owner`/`admin`. Поддержка не может отправлять рассылки. Команда и кнопки
работают только в личном чате сотрудника. Черновики и итоги доступны повторно
через `/announce`, в том числе после перезапуска.

Аудитории: все Telegram-профили, с действующей подпиской, без действующей
подписки. Действие определяется выданным заказом с будущим `expire_at`;
подписки, созданные только вручную в панели без заказа в БД, сюда не входят.
Список получателей фиксируется при сохранении черновика. В предпросмотре
показывается это число. Черновик без получателей отправить нельзя.

Текст — обычный текст до 3000 UTF-16 единиц, без HTML-разметки. Необязательный
`promo=SALE_20` удаляется из тела и становится кнопкой. Код должен быть активен,
не просрочен и не исчерпан. При нажатии получателем обычные правила промокода
проверяются заново. Предпросмотр сам не активирует код.

Подтверждение действует 20 минут и переводит черновик в очередь один раз.
Отменить можно только черновик. Перед каждой доставкой проверяются права
автора; отзыв роли останавливает оставшиеся отправки. Уведомления отправляются
отдельно и не заменяют открытый кабинет получателя.

Telegram не предоставляет ключ идемпотентности для `sendMessage`.
Явный `429` переносит попытку по `retry_after`; обычный отказ `4xx` считается
ошибкой. Таймаут, сетевой обрыв или `5xx` дают статус «без подтверждения»:
автоматического повторного сообщения нет, поскольку первое могло дойти.
Незавершённый захват через 5 минут также становится неподтверждённым.
Итоги отдельно показывают доставленные, ошибки, неподтверждённые и ожидающие.

## Компенсация поддержки

Выдаётся 3 дня на одно открытое обращение. Повторное нажатие сотрудником
продолжает тот же заказ, не создавая новый. В истории обращения автоматически
сохраняется запись; Telegram-уведомление клиенту отправляется отдельно, его
сбой не отменяет выдачу и запись истории.

`SUPPORT_COMPENSATION_DAILY_DAYS=14` ограничивает суммарное число дней на
сотрудника за последние 24 часа: при выдаче по 3 дня это четыре компенсации.
`0` отключает новые компенсации для ограниченных сотрудников. `ADMIN_IDS`
и активная роль `owner` освобождены от лимита; `admin` остаётся под лимитом.
Дальнейшая ручная выдача владельцем доступна через `/grant`.

Лимит, аудит, запись истории и оплаченный заказ сохраняются одной транзакцией.
Параллельные запросы сериализуются по сотруднику и обращению. Если панель
недоступна, заказ остаётся в очереди, а лимит остаётся занят: фоновая выдача
продолжит этот же заказ. Освобождать лимит при таком сбое нельзя — иначе
последующее восстановление выдаст дни сверх лимита. Это намеренное отличие
от поведения Python при ошибке внешнего API.

## Вебхук Remnawave

В окружении бота задайте `REMNAWAVE_WEBHOOK_SECRET`. В панели укажите адрес
`https://<домен>/webhooks/remnawave` и тот же секрет как `WEBHOOK_SECRET_HEADER`.
Без секрета endpoint отвечает `404`. Секрет бота читается только из окружения.

Заголовок `X-Remnawave-Signature`: hex HMAC-SHA256 исходного тела, без
пересериализации JSON. Максимальный размер тела 1 МиБ. Неизвестные подписанные
события подтверждаются без действий. Ошибка записи события в БД возвращает
`503`, чтобы панель могла повторить доставку. Сохраняется хеш тела и минимум
полей уведомления, а не исходный JSON и не HWID.

Поддерживаются плоские `data.telegramId` и вложенные `data.user.telegramId`,
целое число или строка. Для устройства используются `deviceModel`, `platform`,
`osVersion` из `data.device` либо `data`. Неизвестным Telegram-профилям
уведомления не отправляются. Повтор одного тела не создаёт второе действие;
уведомления одного профиля ограничены окном 5 минут в PostgreSQL.
Пауза сохраняется после перезапуска. Явный `429` повторяется по задержке
Telegram, неоднозначная доставка автоматически не повторяется.

Сам endpoint ещё не подключает панель к боту: для приёма реальных событий
нужно настроить её отправку и публичный HTTPS-адрес.
