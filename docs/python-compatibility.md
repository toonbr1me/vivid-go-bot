# Совместимость с Python и обновлённая поддержка

Изменения работают со встроенными ресурсами Vivid. Для их использования не
нужны дополнительные темы, файлы оформления или настройки конкретного сервера.

## Существующая база

`0009_python_orders.sql` сохраняет исходный `legacy_status`. Уже выданные
Python-заказы `paid`, `manual_granted`, `trial_granted` с `provisioned_at`
получают статус `provisioned`; `declined` становится `failed`. Даты и суммы
не меняются. Повторный запуск миграций не перезаписывает исходный статус.
Бесплатные выдачи не учитываются как платные покупки. Операционная очередь
считает ожидающими выдачи только заказы без `provisioned_at`.

Журнал Python хранит `subscription_target` как `{target, prior}`, а Go —
как строку даты. Расчёт зарезервированного срока и восстановление выдачи
читают оба формата и используют прежний абсолютный срок. Исторические
записи журнала не переписываются.

`dbcheck -json` выводит результат миграции и проверки инвариантов. Ошибка
проверки или нарушение инварианта приводит к ненулевому коду завершения.
Перед применением к рабочей установке необходимы резервная копия и проверка
на отдельном снимке; запуск приложения применяет миграции автоматически.

## Платежи

Подтверждённое событие Platega требует суммы, валюты и ID транзакции.
Обычный платёж сопоставляется с ID созданного счёта; рекуррентные списания
связываются отдельно. Ссылки без известного срока действия не выбираются
для повторного checkout и напоминаний; подтверждение старой оплаты остаётся
возможным по существующему заказу.

## Telegram-поддержка

Клиент получает отдельный новый ответ. Первое сообщение подтверждает создание
обращения, последующие сообщения не вызывают повторную отправку истории.
Свои сообщения клиент сохраняет в чате. Полная история и вложения доступны
по кнопке, длинная переписка разбивается на страницы.

Карточка сотрудника содержит последнее сообщение, Telegram ID, ID аккаунта,
имя профиля, Remnawave ID/UUID и состояние подписки. Чтение идентификаторов
не изменяет профиль панели. В клиентском представлении служебные поля
отсутствуют. Уведомления сотрудника, помощника и передачи человеку различаются.

Списки клиента и очередь сотрудника имеют страницы по 10 записей, стрелки,
переход к первой/последней странице и счётчик. Для одинаковых дат используется
ID как дополнительный ключ сортировки. Устаревшая страница ограничивается
текущим диапазоном; возврат из карточки сохраняет страницу до перезапуска.

## Проверки

Полный integration suite запускается скриптом `scripts/test.ps1 -Integration`
на выделенной PostgreSQL через `TEST_DATABASE_URL`. Скрипт также выполняет
`go vet` и JavaScript-тесты. База приложения и внешние Telegram, платёжные
сервисы и панель в этих тестах не используются.

Отдельные регрессии покрывают Python-статусы и журнал выдачи, Platega с
неполными/чужими реквизитами, многостраничные обращения, чужой доступ,
доставку только последнего сообщения и видимость служебных идентификаторов.
