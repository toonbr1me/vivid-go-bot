# Telegram Mini App

Кнопка «Кабинет» открывает `SITE_BASE_URL/app`. Если `SITE_BASE_URL` не задан,
используется `PUBLIC_BASE_URL`. Нужен публичный HTTPS-адрес.

Бот сверяет стандартную кнопку меню при запуске и каждые 15 минут. При
смене домена ссылка обновляется автоматически; после ошибки Telegram
повтор выполняется через минуту, без остановки бота. Персональные кнопки,
заданные отдельно для конкретного чата, имеют приоритет в Telegram.
Основное приложение в профиле бота (`startapp`) настраивается отдельно
через BotFather — Bot API не предоставляет его URL в `setChatMenuButton`.

`/app` подключает официальный SDK и передаёт исходный `initData` в
`POST /auth/telegram`. Сервер проверяет HMAC с токеном именно этого бота,
однозначность полей, возраст подписи до часа и идентификатор пользователя.
`initDataUnsafe` и переданный клиентом ID аккаунта для входа не используются.
Вход выбирает существующий Telegram-аккаунт и не объединяет его с чужой
браузерной сессией. Все бизнес-действия продолжают требовать CSRF.

Для Telegram Web разрешены только фреймы с `web.telegram.org` и его
поддоменов. Админка и партнёрский кабинет сохраняют запрет встраивания.
Сессия Mini App отдельная: Secure, HttpOnly, SameSite=None, Partitioned;
обычная авторизация сайта остаётся отдельной. Страница входа не кэшируется.
Оплата открывается отдельной кнопкой вне фрейма Telegram; возврат и история
не подтверждают оплату без проверки шлюза.

Без SDK или подписи открывается понятная инструкция со входом по коду.
Если подпись устарела, приложение нужно закрыть и открыть снова в Telegram.

Проверки: подмена подписи, другой бот, повторяющиеся поля, старая/будущая
дата, CSRF, сохранение единого аккаунта, ограничения iframe, сессия после
перехода, переход к оплате и исправление старого домена кнопки. JavaScript
проверяется отдельно на повторную отправку, ошибки и опасные редиректы.

Протокол: https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app
Кнопка меню: https://core.telegram.org/bots/api#setchatmenubutton
