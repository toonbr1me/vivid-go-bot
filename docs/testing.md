# Проверки проекта

Тесты не отправляют сообщения в Telegram и не выполняют реальные списания.
Вместо провайдеров и Bot API используются локальные HTTP-серверы и поддельные
клиенты; выдача доступа проверяется с поддельной панелью и настоящей PostgreSQL.
Недоступность виджетов в production не мешает этим проверкам.

## Запуск на Windows

```powershell
# Проверки без обязательной БД. При отсутствии TEST_DATABASE_URL
# интеграционные тесты явно пропускаются.
./scripts/test.ps1

# Полная проверка. Адрес указывает только на отдельную тестовую БД.
$env:TEST_DATABASE_URL='postgres://user:password@127.0.0.1:55439/vivid_test?sslmode=disable'
./scripts/test.ps1 -Integration -Coverage
```

Скрипт выполняет Go-тесты без кеша, `go vet` и JavaScript-тесты виджета.
С `-Coverage` он создаёт `.codex-attachments/coverage.out` и интерактивный
`.codex-attachments/coverage.html`. `-Integration` запрещает незаметно
пропустить проверки БД. Переменная `DATABASE_URL` никогда не используется
тестовой обвязкой. `.env` приложения скрипт не загружает.

В тестовой БД схемы пакетов пересоздаются и очищаются. Обвязка до подключения
проверяет имя БД: `test...`, `..._test` или `..._test_...`. Не указывайте в
`TEST_DATABASE_URL` рабочую БД даже с подходящим названием. Тестовому
пользователю нужны права на создание схем, таблиц, функций и триггеров.

## Linux / macOS и дополнительные режимы

```sh
make test
make test-db TEST_DB='postgres://user:password@localhost/vivid_test?sslmode=disable'
make test-race TEST_DB='postgres://user:password@localhost/vivid_test?sslmode=disable'

# Поиск необычных Unicode/HTML-строк, которые могут потеряться при пагинации.
go test ./internal/bot -run '^$' -fuzz '^FuzzSupportPaginationPreservesText$' -fuzztime=30s
```

На Windows проверка гонок запускается через `./scripts/test.ps1 -Integration -Race`.
Нужны `CGO_ENABLED=1` и совместимый C-компилятор. Скрипт сообщает об отсутствии
поддержки, а не заменяет проверку гонок обычным прогоном.

## Какие риски проверяются

GitHub Actions: `.github/workflows/test.yml` поднимает отдельную PostgreSQL 17,
запускает весь набор с `-race`, `go vet`, 16 JavaScript-проверок и сохраняет
отчёты покрытия. Настройки действий сверены с официальными
[checkout](https://github.com/actions/checkout),
[setup-go](https://github.com/actions/setup-go),
[setup-node](https://github.com/actions/setup-node),
[upload-artifact](https://github.com/actions/upload-artifact/releases).

Сквозной `TestLegacyPurchaseConnectionSupportAndRestartJourney` проверяет
покупку, задержку выдачи, перезапуск, подключение, поддержку с фото и закрытие
обращения для обоих транспортов legacy. Подробности в [описании сценариев](customer-flow.md).

| Область | Проверяемое поведение |
| --- | --- |
| Оплата | Создание заказа до запроса провайдеру, проверка суммы, валюты и ID по API, отсутствие доверия к поддельным полям вебхука |
| Автопродление | Явное согласие, поддержка конкретного способа, выключенный env-флаг, дата списания, отсутствие сохранённой карты, изменение цены и периода |
| Повторы | Постоянный ID при таймауте, остановка вне окна идемпотентности, несколько планировщиков, повторные callback, отдельный заказ на следующее списание |
| Отмена | Подтверждение отмены Platega, сохранение включённого состояния при ошибке провайдера, изоляция аккаунтов |
| HTTP-вебхуки | Авторизация, повреждённый JSON, лимит тела, неоплаченный статус, сохранение события перед ответом, ошибка БД без ложного подтверждения |
| Чистый чат | Доставка до удаления, отказ Telegram, запрет удаления в группе, выключенная очистка, сохранение сообщения при сбое записи |
| Production без виджетов | Legacy не вызывает widget API; отказ создания/обновления сохраняет старую карточку и команду пользователя |
| Поддержка | Проверка владельца при чтении и ответе, атомарное создание обращения и сообщений, полный текст при разбиении, закрытое обращение |
| Данные | Повторные миграции не сбрасывают настройки, единственное включённое соглашение, транзакцию нельзя перепривязать к другому заказу |
| Интерфейс | Экранирование текста в rich/HTML, границы пагинации, подтверждение галочки сервером, блокировка повторных нажатий и восстановление после ошибок |
| Фоновые задачи | Продолжение после временной ошибки, остановка по контексту, повтор недоставленного напоминания, запрет повторных начислений |

Тесты содержат умышленно повреждённые запросы и инъекции ошибок в тестовой БД.
Предупреждения об отклонённых платежах и временных сбоях в их выводе ожидаемы;
результат определяется итогом теста.

Эти проверки не подтверждают разрешения конкретного магазина, возможность
реального списания, доступность новых виджетов в Telegram или обработку deep link
конкретной установленной версией мобильного приложения. Для этого после
восстановления production нужны отдельные проверки на стороне сервисов.
